인터넷에 이미 수만 개씩 있는 **건반형 BMS(4K/5K/7K)** 를 열어 뮤즈 대시의 두 레인
(**지상 `13` · 공중 `14`**)으로 접습니다. 리듬을 손으로 다시 찍지 않아도 됩니다.

> [!IMPORTANT]
> **나오는 것은 리듬 뼈대이지 완성된 채보가 아닙니다.**
> 건반 BMS 에는 하트·장애물·고스트·보스 같은 뮤즈 대시 노트 종류 정보가 **아예 없습니다.**
> 변환 결과는 전부 일반 노트와 홀드뿐이고, 종류는 사람이 얹어야 합니다.

| 질문 | 답 |
|:---|:---|
| 어디에 있나 | **편집(E) 메뉴 → `건반 BMS 가져오기 (다운믹스)...`** |
| 무엇이 필요하나 | **원본 건반 BMS 하나뿐.** 뮤즈 대시 차트도, WAV 파일도 필요 없습니다 |
| 무엇이 나오나 | `13`·`14` 두 레인의 일반 노트와 홀드. 제목·BPM·변속·마디 길이도 함께 가져옵니다 |

| 되돌릴 수 있나 | **예. `Ctrl+Z` 한 번**이면 노트·헤더가 가져오기 전으로 돌아갑니다 (같이 연 음원·영상은 남습니다) |

## 1. 쓰는 법

1. **편집(E)** → `건반 BMS 가져오기 (다운믹스)...`
2. 원본 파일을 고릅니다 (`.bms` · `.bme` · `.bml` · `.pms`)
3. 지금 문서에 노트가 있으면 **확인 창**이 뜹니다 — *"노트 N개를 모두 지우고 변환 결과로 채웁니다"*
4. **결과 창**이 지상·공중 노트 수, 홀드 쌍, 레인 배분(과 손댄 자리), 옮긴 수·버린 수, 짝 검사 요약을 알려 줍니다
5. 마음에 안 들면 **`Ctrl+Z` 한 번** — 노트·헤더가 돌아갑니다. 같이 연 음원·영상은 남습니다

> **곡 폴더째 가져오기 (2026-09-21).** 고른 차트와 같은 폴더에서 음원(`.ogg`)과 영상을 찾아 같이 엽니다.
> 고르는 규칙은 폴더 열기와 같습니다 — 폴더 이름과 같은 파일이 있으면 그것, 없으면 이름순 첫 번째
> ([`FolderMedia`](../../muse%20dash%20bms%20editer/Services/FolderMedia.cs)). 파일을 복사하지는 않습니다.
> 음원이 깨져 있어도 **가져오기는 실패하지 않습니다** — 노트는 이미 들어왔고, 결과 창에 사유만 적습니다.

> [!CAUTION]
> **가져오기는 덮어쓰기입니다.** 기존 노트 위에 얹지 않습니다.
> 얹으면 어느 것이 변환 결과인지 알 수 없고, 같은 자리가 겹치면 저장할 때 한쪽이 조용히 사라집니다
> (라이터 중복 노트 버그 → [muse_dash_specialization.md §2-2](../plans/muse_dash_specialization.md)).

### 거절하는 경우

| 문구 | 뜻 |
|:---|:---|
| *"그 파일에서 건반 노트를 찾지 못했습니다"* | 1P 건반 채널(`11~19`)에 노트가 없습니다 |
| *"조건 분기가 있는 BMS는 먼저 분기를 확정해야..."* | `#RANDOM`/`#IF` 차트입니다. 갈래를 확정한 파일로 가져오십시오 |
| *"변환 결과가 비었습니다"* | 건반 노트가 전부 걸러졌습니다 |
| *"확인 창을 띄울 수 없어 가져오기를 멈췄습니다"* | 확인 없이 덮어쓰지 않습니다 |

## 2. 무엇을 읽는가

### 2-1. 건반 채널 — 화면에 놓인 왼쪽→오른쪽 순서

| 왼쪽 ← | | | | | | | → 오른쪽 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| `16` | `11` | `12` | `13` | `14` | `15` | `18` | `19` |

`16`(스크래치)을 **가장 왼쪽**으로 봅니다. 이 순서가 곧 레인 배분 규칙입니다([§3](#3-어디로-접는가--레인-배분)).
**2P 쪽(`21~29` · `61~69`)은 건너뜁니다** — 뮤즈 대시에 자리가 없습니다. 결과 창에 한 번 알립니다.

### 2-2. 롱노트 — 시작·끝 노트로만 읽습니다

원본 게임(스타트레일 · 스타게이저 · 건볼트 등)은 롱노트를 **건반 채널에 찍힌 시작 노트와 끝 노트**로 적습니다.
어느 것이 시작이고 끝인지는 키음 값이나 `#WAV` 파일명이 정하고, 그 규칙은 게임 프로파일에 있습니다(→ [§2-3](#2-3-게임-프로파일--롱노트를-키음-쪽에-적는-게임들)).

일반 BMS의 롱노트 표기 두 가지는 **읽지 않습니다.**

| 표기 | 어떻게 되나 | 왜 |
|:---|:---|:---|
| **채널 `51~59`** | 건너뜁니다. 건너뛴 수를 결과 창에 적습니다 | 원본 게임들이 읽지 않는 채널입니다. 읽으면 **게임에 없던 홀드**가 생깁니다 |
| **`#LNOBJ xx`** | 해석하지 않습니다. 키 `xx` 가 찍힌 자리는 일반 노트로 남습니다 | 마찬가지로 원본 게임들이 읽지 않습니다 |

게임을 알아보지 못한 차트는 롱노트 없이 **전부 일반 노트**로 나옵니다.

> **2026-09-21 변경.** 처음에는 두 표기도 롱노트로 읽었습니다. 실측 20곡에는 둘 다 한 줄도 없었고
> (홀드 165개 전부 게임 프로파일 경로), 게임 폴더의 차트에 그런 줄이 섞여 있으면 게임에 없던 홀드를
> 만들 수 있어서 뺐습니다. 뺀 뒤에도 20곡 수치는 [§6](#6--실측-2026-09-21-재측정)과 똑같습니다.

### 2-3. 게임 프로파일 — 롱노트를 키음 쪽에 적는 게임들

여러 리듬게임이 롱노트를 **채널이 아니라 키음에** 적습니다. 그 규칙은 이미
[`Profiles/*.json`](../../muse%20dash%20bms%20editer/Profiles) 에 있고 짝 맞추는 엔진(`HoldPairingEngine`)도 이미 있어서,
**다운믹서는 규칙을 다시 적지 않고 그대로 빌려 씁니다.**

```
차트 경로 → GameProfileCatalog.DetectFromPath (폴더 이름으로 게임 판별)
         → 그 게임 규칙으로 HoldPairingEngine.Pair
         → 짝이 잡힌 노트를 롱노트 시작·끝으로 표시
         → 다운믹서가 뮤즈 대시 홀드로 변환
```

| 게임 | 롱노트를 어디에 적나 | 근거 |
|:---|:---|:---:|
| 식스타 게이트: 스타트레일 | 키음 값 `02`=시작 · `03`=끝 | Source |
| 건볼트 레코즈 사이크로니클 | 키음 코드 `02`=시작 · `19`=끝 · 페어리 `11~18`→`1A`/`1B` | Source |
| 식스타 게이트: 스타게이저 | `#WAV` 파일명 | Assumed |
| DEFLATE · UNBEATABLE | `#WAV` 파일명 | Source |

판단이 들어간 자리 셋:

* **게이트는 홀드로 안 옮깁니다.** 스타트레일의 게이트(`04`/`05`)는 무대 장치 열림/닫힘이지
  플레이어가 붙잡는 노트가 아닙니다. 건볼트 페어리는 플레이어 노트라 옮깁니다.
* **채널을 건너뛰는 짝은 버립니다.** 게이트처럼 레인을 가로지르는 짝은 뮤즈 대시 홀드로 표현할 수 없습니다.
* **모르는 게임이면 키음 값을 해석하지 않습니다.** 일반 BMS에서 키음 `02`는 그냥 다른 소리인데
  롱노트로 읽으면 **없는 홀드를 만들어냅니다.** 테스트로 못 박아 두었습니다.

버린 것은 전부 결과 창에 적습니다.

## 3. 어디로 접는가 — 레인 배분

**그 게임의 화면 배치를 아는 프로파일이 있으면 그것을 따릅니다.** 없을 때만 채널 번호로 짐작합니다.

### 3-1. 게임이 배치를 알려 주는 경우 (2026-09-21 추가)

| 게임 | 지상 `13` | 번갈아 | 공중 `14` | 어디서 옮겨 적었나 |
|:---|:---|:---:|:---|:---|
| **건볼트 레코즈 사이크로니클** | `16` `11` `12` (왼쪽 3레인) | — | `14` `15` `18` (오른쪽 3레인) | `ChannelToLaneMap` 의 `(Lane, IsLeft)` |
| **식스타 게이트: 스타트레일** | `16` `11` `12` | `13` | `14` `15` `18` | `LaneMapping` `16`=0 … `18`=6 (왼→오른쪽) |
| **식스타 게이트: 스타게이저** | `13` (아래) | `12`(오른쪽) · `11`(왼쪽) | `16` (위) | `BmsChannelLaneOrder` — 좌우가 아니라 **4방향** |

값은 [`Profiles/*.json`](../../muse%20dash%20bms%20editer/Profiles) 의 `downmix` 칸에 있고, 근거 코드가 `source` 에 같이 적혀 있습니다.
**추측으로 채우지 않습니다** — 옮겨 적을 소스가 없는 게임(DEFLATE · UNBEATABLE)은 이 칸을 비워 두고 아래 기본 규칙을 씁니다.

> 결과 창 첫 줄이 어느 쪽을 썼는지 말해 줍니다 —
> `레인 배분 (건볼트 레코즈 사이크로니클 화면 배치): 16 → 지상 · 11 → 지상 · …`

> [!IMPORTANT]
> **그 게임이 노트로 읽지 않는 채널은 버립니다.** 건볼트는 `13` 을, 스타게이저는 `14`·`15`·`18` 을
> 노트 채널로 읽지 않습니다. 거기 적힌 줄을 노트로 만들면 **게임에 없던 노트**가 생깁니다.
> 버린 수는 결과 창에 적습니다.

### 3-2. 프로파일이 없을 때 — 채널 번호로 짐작하기

**왼쪽 절반 → 지상, 오른쪽 절반 → 공중, 가운데 하나가 남으면 번갈아.** `16`은 항상 지상입니다.

| 원본 | 지상 `13` | 번갈아 | 공중 `14` |
|:---|:---|:---:|:---|
| **4K** (`11~14`) | `11` `12` | — | `13` `14` |
| **5K** (`11~15`) | `11` `12` | `13` | `14` `15` |
| **7K** (`11~15` `18` `19`) | `11` `12` `13` | `14` | `15` `18` `19` |
| 스크래치 | `16` | — | — |

> 비어 있는 건반이 있어도 **실제 번호의 좌우 위치를 유지합니다.** 쓰이는 채널만 세어 자리를 당기면
> 같은 게임의 곡마다 배분이 달라집니다.

**왜 좌우로 가르나.** 왼손/오른손을 그대로 위아래로 옮기는 것이라, 건반에서 좌우로 오가던 트릴이
뮤즈 대시에서 **지상·공중 번갈아 치기**가 됩니다. 한 레인 연타로 뭉개지지 않습니다.

### 3-3. 그래도 쏠리면 — 무거운 레인을 번갈아로 돌립니다

배치를 옳게 따라도 **원본 채보가 한쪽 손에 몰려 있으면** 결과가 기웁니다.
실측에서 스크래치·게이트 레인 하나가 곡 노트의 **43%**를 차지한 차트도 있었습니다(rise의 `16`).
그대로 접으면 지상만 쉴 새 없이 두드리는 채보가 되고, 그건 **원본에 없던 난이도**입니다.

그래서 마지막에 한 단계를 더 둡니다.

```
지상 비율이 45~55% 밖이면
  → 쏠린 쪽에서 가장 무거운 레인을 하나 골라 번갈아로 돌린다
  → 다시 재고, 더 나아지지 않으면 멈춘다
```

* **반대편으로 통째로 옮기지 않습니다.** 옮기면 그 레인의 연타가 반대쪽에서 똑같이 뭉칩니다.
  번갈아로 돌리면 한 레인의 연타가 지상·공중을 오가는 패턴이 되는데, **그게 뮤즈 대시에서 실제로 치는 모양**입니다.
* 무거운 레인부터 보고, 같은 값이면 채널 번호 순으로 고릅니다. **같은 차트는 몇 번을 돌려도 같은 결과**가 나옵니다.
* 손댄 자리는 결과 창에 적고, 레인 배분 줄에도 `16 → 번갈아(쏠림 교정)` 처럼 표시합니다.
  게임 배치에서 온 번갈아와 교정으로 생긴 번갈아를 구별하려는 것입니다.

> [!NOTE]
> **효과 (20곡 실측):** 지상 비율 **72.1% → 50.7%**, 20곡 **전부** 45~55% 안(47.8%~54.8%)에 들어왔습니다.
> 노트 수·홀드 수·버린 수는 **하나도 안 바뀌었고**, 오히려 자리다툼(옮김)이 1,088 → **756**으로 줄었습니다.

## 4. 무엇을 옮기고 무엇을 버리는가

뮤즈 대시는 **손이 둘(지상·공중)뿐**입니다. 건반 게임의 3~5 동시치기를 그대로 옮기면 칠 수 없는 패턴이 됩니다.

| 상황 | 어떻게 되나 |
|:---|:---|
| 가고 싶은 레인의 **같은 자리가 찼다** | **반대 레인으로 옮깁니다** (결과 창의 *옮김*) |
| 반대 레인도 찼다 | **버립니다** — 같은 자리에 셋 이상 (결과 창의 *버림*) |
| 그 레인을 **홀드가 지나는 중**이다 | 아무것도 못 올립니다. 한 손으로 둘을 못 잡습니다 |
| 홀드끼리 겹쳐 두 레인 다 막혔다 | 그 **홀드를 버립니다** |
| **길이가 0**인 홀드 | 버립니다 |

홀드의 시작과 끝은 **반드시 같은 레인에 붙여서** 내려보냅니다. 뮤즈 대시는 같은 채널에서 나온
**순서**로 시작·끝을 가르기 때문에, 사이에 다른 홀드가 끼면 `시작·시작·끝·끝` 이 되어 짝이 통째로 뒤집힙니다.
그래서 위의 겹침 규칙이 곧 **짝 안전장치**입니다 — 변환 결과를 짝 검사기에 그대로 넣어 0건인지 테스트가 확인합니다.

## 5. 자동으로 만들어지는 키음 정의

가져오기는 원본의 `#WAV` 표를 남겨 둔 채(BGM이 참조합니다) **빈 번호 6개에 뮤즈 대시 노트 정의를 새로 적습니다.**

| 쓰임 | UID | 파일명 |
|:---|:---:|:---|
| 지상 일반 | `011001` | `1번 씬 wav폴더\011001_일반 노트1 지상 노멀_dt1.48.wav` |
| 공중 일반 | `011004` | `1번 씬 wav폴더\011004_일반 노트1 공중 노멀_dt1.48.wav` |
| 지상 홀드 시작 / 끝 | `010201` | `...\010201_홀드 지상 시작 노트_dt1.48.wav` · `...끝 노트...` |
| 공중 홀드 시작 / 끝 | `010204` | `...\010204_홀드 공중 시작 노트_dt1.48.wav` · `...끝 노트...` |

* **씬은 `01` 고정**입니다. 다른 씬을 쓰려면 가져온 뒤 키음 팔레트에서 바꿉니다.
* 파일명의 *시작*/*끝* 은 **짝을 정하지 않습니다.** 짝은 같은 채널에서 나온 순서가 정합니다
  (→ [muse_dash.md](muse_dash.md)). 이름은 사람이 읽으라고 붙은 것입니다.
* 원본의 **건반 데이터 줄과 `#LNOBJ`/`#LNTYPE` 헤더는 보존줄에서 걷어냅니다.** 남겨 두면 저장할 때
  건반 채널이 그대로 따라 나옵니다.

> [!WARNING]
> **소리는 따로입니다.** 이 기능은 노트 **정의**만 만듭니다.
> 미리듣기와 게임에서 소리가 나려면 그 씬의 **WAV 폴더가 차트 폴더 옆에 있어야** 합니다.
> 오디오 파일 자체를 만들거나 복사하지는 않습니다.
